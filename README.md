# Kago Analytics

Аналитика и партнёрская панель для VPN-бота (Remnashop). Данные попадают в панель двумя способами, их можно совмещать:

- **прямое подключение к БД бота** — панель сама раз в минуту читает изменения из PostgreSQL бота (только чтение), в коде бота ничего менять не нужно;
- **приём событий** — бот сам отправляет события POST-запросами на `/api/ingest`.

Оба способа пишут в одну базу панели, и id событий у них совпадают, поэтому дублей не бывает.

- **Партнёры** («рефералодатели») входят по логину и паролю и видят статистику только своих пользователей: регистрации, триалы, покупки, конверсию, выручку, графики, географию, платформы, список пользователей и своё вознаграждение.
- **Администратор** видит общую статистику: всех пользователей, выручку по валютам, платёжки, тарифы, источники трафика (органика / рефералы / рекламные ссылки), рейтинг партнёров. Он же управляет партнёрами, выдачами и токеном бота.
- **Telegram-бот KAGO REFERRER** — управление реферерами из Telegram поверх той же базы: добавить реферера, выдать ему реферальную ссылку, видеть приглашённых и покупки, записывать выдачи дней. Реферер в боте видит свою ссылку и начисления и получает уведомления о новых приглашённых и покупках.

## Реферальные ссылки и Telegram-бот

KAGO REFERRER — отдельная система: панель и бот стоят на своём сервере и ни к чему больше не подключаются.

```
реферер делится ссылкой https://<домен панели>/r/<код>
        │
        ▼
человек открывает её → панель засчитывает реферала → перенаправление на https://usekago.net
        │
        ▼
бот: рефереру «+1 реферал», админу «нужно выдать N дней» с кнопкой «✅ Выдал»
```

**1 день подписки за каждого реферала** (меняется в боте → «Правила начисления» и индивидуально у реферера). Дни вы выдаёте сами, бот только сообщает, кому и сколько, и записывает выдачу по кнопке.

Ссылка не знает, кто именно её открыл, поэтому реферал засчитывается один раз на человека настолько, насколько это видно по ссылке:
- превью ссылок в Telegram, WhatsApp и т. п., краулеры и скрипты не считаются;
- браузер, который уже приходил по любой реферальной ссылке, повторно не считается (cookie; засчитывается первому рефереру);
- адрес, с которого реферал уже был засчитан за последние 30 дней, повторно не считается. IP хранится только в виде хэша с секретом; IPv6 учитывается по /64.

Все переходы, засчитанные и нет, видны в карточке реферера → «👥 Переходы» с причиной.

### Установка

```bash
git clone -b claude/exciting-hamilton-if0vg6 https://github.com/ifdef2635/panel_referers.git && cd panel_referers
sudo BOT_TOKEN='123456:ABC...' BOT_ADMIN_IDS=5689226201 bash deploy/install.sh
```

Нужен домен панели: адрес ссылок строится из него (`PUBLIC_URL`). Куда вести людей, задаёт `REFERRAL_REDIRECT_URL` (по умолчанию `https://usekago.net`). Настройки хранятся в `/etc/kago/kago.env`, после изменения выполните `systemctl restart kago-analytics kago-bot`.

### Что умеет бот

**Администратор** (`/start` или `/menu`):
- сводка: рефереры, переходы, засчитанные рефералы, начислено / выдано / к выдаче;
- **➕ Добавить** — Telegram ID, @username (если человек писал этому боту) или пересланное сообщение. Бот создаёт реферера, отправляет ему ссылку и выдаёт логин и пароль в веб-кабинет;
- карточка реферера: ссылка, переходы, рефералы, начисления; **🎁 Выдать** (записывает выдачу и уведомляет реферера), выдача произвольного числа дней или корректировка; **👥 Переходы**; отправка ссылки, новая ссылка (старая перестаёт работать), индивидуальная ставка, новый пароль в панель, история выдач, отключение и удаление;
- уведомления «🎁 Рефереру X нужно выдать N дней» с кнопкой «✅ Выдал N дней» (раз в `BOT_NOTIFY_SECONDS`, по умолчанию 5 минут).

**Реферер** (`/start`, `/link`): своя ссылка, переходы, рефералы, начислено / выдано / к выдаче, кнопка в веб-кабинет, уведомления о новых рефералах и выдачах.

Бот может писать человеку, только если тот сам его запустил. Аватар бота лежит в `deploy/bot_avatar.png`, поставить его можно в @BotFather → `/setuserpic`.

## Прямое подключение к БД бота

Укажите строку подключения при установке (`REMNASHOP_DSN=... bash deploy/install.sh`) или в `/etc/kago/kago.env`, затем выполните `systemctl restart kago-analytics`:

```
REMNASHOP_DSN='postgresql://user:pass@host:5432/remnabot'
REMNASHOP_SYNC_SECONDS=60
```

При первом проходе загружается вся история, дальше — только изменения (по `updated_at`). Статус, кнопки «Проверить подключение» и «Синхронизировать сейчас» есть в разделе «Интеграции». Из консоли: `sudo kago check-bot-db` и `sudo kago sync-bot-db [--full]`.

Нужны права `SELECT` на `users`, `referrals`, `transactions`, `subscriptions`, `ad_links` (схема Remnashop после миграции 0026). Если схема не совпадает, проверка скажет, какой таблицы или колонки не хватает.

## Приём событий

Формат описан в [`integration/events_api.md`](integration/events_api.md): конверт `{id, type, ts, data}`, идемпотентность по `id`, до 500 событий и 1 МБ на запрос, ответ `{accepted, duplicates, ignored, errors}`.

Типы: `user.registered`, `payment.completed`, `payment.refunded`, `subscription.updated`, `device.added`, а также расширения для партнёрки: `referral.attached`, `user.updated` и поля `referrer_id`, `telegram_id`, `username`, `name` в `user.registered`.

Порядок доставки не важен: дата регистрации берётся самая ранняя, старое состояние подписки не затирает новое, а возврат можно прислать раньше самого платежа.

Токен выпускается в разделе *Интеграции → 2. Приём событий от бота*. Он показывается один раз, перевыпуск сразу отключает старый.

### Подключение бота

В [`integration/`](integration/) лежат готовые файлы (их же можно скачать из раздела «Интеграции»):

| Файл | Что делает |
|---|---|
| `kago_emitter.py` | Модуль для кода бота: `emit()` не блокирует и не бросает исключений, отправка пачками с повторами. Есть хелперы под объекты Remnashop. |
| `remnashop_sync.py` | Выгрузка истории из БД Remnashop (backfill). С флагом `--watch 60` досылает изменения раз в минуту, поэтому интеграция работает **без правок в коде бота**. |

```bash
# на сервере бота
pip install "psycopg[binary]" httpx
export KAGO_URL=https://<панель>/api/ingest KAGO_TOKEN=kago_...
export KAGO_CA_FILE=kago.crt          # пока у панели самоподписанный сертификат
export REMNASHOP_DSN=postgresql://remnashop:<пароль>@127.0.0.1:5001/remnashop
python remnashop_sync.py --watch 60
```

`kago.crt` — копия `/etc/kago/tls/selfsigned.crt` с сервера панели. С этим файлом соединение проверяется, отключать проверку TLS не нужно. Когда у панели появится домен с Let's Encrypt, `KAGO_CA_FILE` можно убрать.

## Как считается

**Кто приведён партнёром.**
- *реферальная ссылка* `/r/<код>` (основной способ) — см. «Реферальные ссылки и Telegram-бот»;
- если подключены данные VPN-бота (ниже), можно также привязать источники в панели:
- *реферер* — пользователь бота, чьей реферальной ссылкой пользуется партнёр (`referrer_id` в событиях); можно включить учёт 2-го уровня;
- *источник* — рекламная ссылка (`source` в `user.registered`).

Один источник принадлежит только одному партнёру, поэтому пользователи не считаются дважды.

**Покупка** — событие `payment.completed` с суммой больше 0, без `is_test` и без последующего `payment.refunded`.

**Вознаграждение** — дни подписки:
- **1 день за каждого приведённого пользователя**;
- **50 % от срока купленной подписки** — только если подключены данные VPN-бота (покупки по реферальной ссылке пока не отслеживаются): за каждую покупку приведённого пользователя, продления тоже. Например, за тариф на 30 дней начисляется 15. Срок берётся из `plan_snapshot.duration` транзакции Remnashop (`duration_days` в событии `payment.completed`). Покупки бессрочных тарифов и покупки без известного срока процентом не вознаграждаются.

Ставки меняются глобально в «Настройках» (дни за реферала — и в боте → «Правила начисления»), а также индивидуально у партнёра. Начисления пересчитываются по текущим правилам. Панель и бот показывают *начислено / выдано / к выдаче*. Сами дни администратор выдаёт вручную и отмечает выдачу в боте или в панели. Возврат платежа отменяет начисление.

## Установка на Ubuntu (22.04 / 24.04)

```bash
git clone https://github.com/ifdef2635/panel_referers.git
cd panel_referers
sudo bash deploy/install.sh
```

Скрипт:
1. ставит PostgreSQL, Python-окружение, nginx и certbot, создаёт свою БД `kago`;
2. разворачивает код в `/opt/kago-analytics`, конфиг пишет в `/etc/kago/kago.env`;
3. настраивает systemd-службу `kago-analytics` (uvicorn на 127.0.0.1:8090 с изоляцией);
4. включает HTTPS: с доменом и e-mail — Let's Encrypt с автопродлением, без домена — самоподписанный сертификат на IP сервера; HTTP перенаправляется на HTTPS;
5. включает ежедневный `pg_dump` (хранится 14 копий);
6. выводит адрес, логин и пароль админа, токен бота и `curl` для проверки.

Без вопросов: `sudo DOMAIN=stats.example.com LE_EMAIL=me@example.com ASSUME_YES=1 bash deploy/install.sh`.

**Обновление** или подключение домена позже — запустите скрипт ещё раз. Данные, настройки и токен сохраняются.

```bash
sudo kago list                    # аккаунты
sudo kago create-admin LOGIN      # новый админ
sudo kago set-password LOGIN      # сброс пароля
sudo kago issue-token             # новый токен бота (старый перестанет работать)
sudo kago check-bot-db            # проверить подключение к БД бота и её схему
sudo kago sync-bot-db [--full]    # синхронизировать сейчас (--full — всю историю)
journalctl -u kago-analytics -f   # логи
journalctl -u kago-bot -f         # логи Telegram-бота
```

## Разработка и тесты

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt pytest httpx
cp .env.example .env              # укажите DATABASE_URL
uvicorn app.main:app --reload
```

Для тестов нужны две PostgreSQL-базы, обе будут очищены: база панели и база со схемой Remnashop из `tests/remnashop_schema.sql`. Вторая нужна для сквозного теста «Remnashop → sync → ingest → статистика».

```bash
TEST_DATABASE_URL=postgresql+psycopg://u:p@127.0.0.1/kago_test \
TEST_REMNASHOP_DSN=postgresql://u:p@127.0.0.1/remnashop_test pytest
```
